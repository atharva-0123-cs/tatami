# AGENTS.md

TUI "tatami" terminal multiplexer built with `gdamore/tcell/v2`, `creack/pty`, and `charmbracelet/x/vt`. Go module `github.com/atharva-0123-cs/tatami`. Writes debug log to `tatami.log`.

## Build & run

- Build: `go build -o tatami .`
- Run: `./tatami` — requires a real TTY; exits 1 if stdin is not a TTY. Do not test with `</dev/null`.
- Binary `tatami` is gitignored; rebuild after every edit (`go build ./...` only type-checks, does not produce the binary).
- No CI, no linter/formatter config. Checks: `go vet ./...` + `go test ./...`. Unit tests live in `term/`, `pane/`, `layout/`, `config/`, and `falkor/` (e.g. single test: `go test ./term/ -run TestScroll`).

## Architecture

- `main.go` — thin launcher: opens `tatami.log`, bootstraps the structured logger via `setupLogger` (two-phase: defaults then the loaded profile), loads the config, initializes the global FalkorDB client (`falkor.Initialize(cfg)`), runs a bounded startup health check (`GlobalClient.Startup` — logs a warning and continues if FalkorDB is unreachable), then `defer GlobalClient.Close()`, `app.New(cfg)` + `a.Run()`. All screen/loop/key logic lives in `internal/app`.
- `internal/app/` — `App` struct (screen, `*layout.WindowManager`, and the per-loop UI state that used to be package globals in `state.go`: prefix/resize/paste/copy modes, scroll offset, error message, quit flag). `app.go` creates/initializes the tcell screen (paste + mouse when `mouse=on`), installs the `pane.Interrupt` wake-up hook, and runs the `PollEvent` loop (`Run`); `keys.go` is the multiplexer command parser (`handleKey`) with unconsumed keys forwarded to the focused pane; `Cleanup` closes every pane, finishes the screen, and emits xterm reset sequences.
- `config/` — `tatami.conf` loader (`KEY=value`, `#` comments) with `TATAMI_<NAME>` env overrides: prefix key, mouse toggle, status-bar colors, log level/format, pane gap, and the FalkorDB settings `falkordb_host`/`falkordb_port`/`falkordb_graph`/`falkordb_password` (env `TATAMI_FALKORDB_HOST`/`_PORT`/`_GRAPH`/`_PASSWORD`).
- `format/` — custom `slog.Handler` rendering each record as `[LEVEL] time file:line : message key=value...` (the `text` format; `json` uses the stdlib JSON handler).
- `term/` — the pane's screen emulator, a thin adapter over `charmbracelet/x/vt` (the library does all VT100/xterm parsing). `terminal.go` holds the `Terminal` type wrapping a `*vt.Emulator`: it converts the library's `uv.Cell`/`uv.Style` into the small `term.Cell`/`term.Color` (default / palette index / truecolor RGB) the UI draws, and adds the copy-mode scroll view, `AllText` extraction, the window title, and the DECCKM / bracketed-paste (2004) flags the UI reads (tracked via the emulator's mode callbacks). Emulator replies (DA/CPR) are drained from the library's output pipe on a background goroutine and forwarded to the `respond` callback; `Close` unblocks that goroutine by closing the input pipe. It holds no UI/PTY refs and is not internally synchronized (callers serialize via the pane mutex). Tests in `term/terminal_test.go`.
- `pane/pane.go` — `Pane` type + lifecycle: wraps a `creack/pty` running a shell, owns a `*term.Terminal`, spawns the output-reader and process-wait goroutines. `process.go` selects the shell (`shellCandidates`) and starts it; `output.go` (`readPtyOutput`) feeds shell output into the emulator under the pane mutex and wakes the main loop via the `pane.Interrupt` hook (which posts an `EventInterrupt`); `draw.go` paints the border and emulator grid into the screen; `input.go` converts tcell events to the byte sequences the shell expects (`KeyToBytes`/`HandleEvent`) plus clipboard/paste helpers; `clipboard.go` copies text to the system clipboard.
- `window/` — workspace model. `tree.go` has the layout tree primitives (`window.Node`, `SplitDir`/`SplitHorizontal`/`SplitVertical`) with exported `Children`/`Sizes`/`Parent` fields; `window.go` is the `Window` save slot (name/root/focused/paneCount/zoomed); `registry.go` is the `Registry` list of windows with the active-window index/name.
- `layout/layout.go` — `WindowManager` (active-window state root/focused/paneCount/zoomed lives directly on it) embedding a `window.Registry`; the `windows` slice entry at `CurrentWin` mirrors the active state and is refreshed on every switch (`saveCurrent`/`switchTo`). `draw.go` recurses to assign each pane a screen rectangle (insetting first by `edgeInsets` — `SetPaneGap`/`gapGeometry` derive a per-side inset + shared-edge overlap from the `pane_gap` setting so the visible gutter equals the configured cell count, plus a one-cell-smaller `outer` margin on screen-edge sides so panes sit flush at small gaps), calls each pane's `Draw`, and renders the status bar; `splits.go` creates panes, `close.go` removes them (via `windowGone` an emptied window is dropped and a neighbor adopted; `CloseDeadPanes` sweeps all windows), `focus.go` moves focus, `transform.go` zooms/swaps/rotates, `resize.go` adjusts proportions. Changes appear on the next `Draw` pass.
- `falkor/` — FalkorDB (Redis graph) integration plus the code knowledge graph (WIP on branch `hackton`; roadmap in `TODO.md`). `client.go` wraps `go-redis` and sends `GRAPH.QUERY` (`GlobalClient`, `Initialize` reads config including `falkordb_password`). Connection handling is explicit and thread-safe: `Connect` pings on demand and caches success; `HealthCheck` always pings (detects a dropped server) and logs a `falkordb connected`/`connection lost` line on a state change; `Startup` is the boot-time probe (a few retries, never fatal); a transport error marks the client disconnected so the next `Query` reconnects; `Connected`/`Status`/`Addr` expose state for the UI. Code graph: `graph.go` is the in-memory IR (`Node`/`Edge`/`CallRef`, dedup, `Resolve` for same-file-first call resolution, `Cypher` for escaped idempotent MERGE statements); `parser.go` is the `Parser` registry (`.go`/`.py`/`.js`/`.ts`/... to parser); `go_parser.go` uses `go/ast`, `python_parser.go` and `js_parser.go` are regex/indentation scanners; `ingest.go` has `ScanProject` (walk + parse + merge, skips hidden/vendor/node_modules dirs) and `Client.Ingest`/`IndexProject` (clear + write statements); `query.go` runs and formats results; `queries.go` holds the `:name` builtin traversals; `mapper.go` (`LayoutToCypher`) maps the layout tree (separate concern). Schema labels/relationships are in `code_schema.go` (code graph) and `schema.go` (window layout). Wired into the TUI via `internal/app/graph.go`: prefix+`g` indexes the CWD into the graph, prefix+`m` (or the command-mode `cypher` command) opens a bordered Cypher prompt panel (with a completion dropdown; `Tab`/`Shift-Tab` cycle `:name` builtins, Cypher keywords, labels and rel types via `falkor.SchemaTokens`) and its scrollable result overlay, and a background monitor (`startGraphMonitor`) re-probes FalkorDB periodically, waking the loop on a connectivity change so the status bar shows `graph:on`/`graph:off`.

## Keybindings (default Ctrl+A prefix; configurable via `tatami.conf` `prefix =`)

c/-: h-split | C/|: v-split | w: new window | n: next win | p/W: prev win | 1-9: jump to window | x: close | z: zoom | o: rotate | }/{: swap | r: resize mode (then h/j/k/l) | [: copy mode (j/k or ↑/↓ scroll, PgUp/PgDn page, g/G top/bottom, y copy, q/Esc exit; mouse wheel scrolls) | t: FalkorDB connectivity test | g: index CWD into FalkorDB | m: Cypher prompt | : or ;: command mode (see `internal/app/command.go`; includes `cypher` for the Cypher prompt/result overlay) | q: quit | arrows: focus

## Concurrency gotchas (critical)

- The tcell screen buffer may only be touched from the main goroutine: inside the `PollEvent` loop, in an event handler, or from `render()`. Background goroutines (e.g. `readPtyOutput`) must never call `SetContent`/`Show`; they only mutate the emulator under the pane mutex and signal the main loop via `pane.Interrupt` → `screen.PostEvent(NewEventInterrupt(nil))`.
- `PostEvent` is non-blocking: if the event queue is full the wake-up is dropped. That is safe — the main loop is already processing a queue of pending events, so a render is imminent.
- The initial pane is created by `app.New` (via `wm.NewPane`) before `Run` starts; `wm.Draw` also creates one lazily if the tree is empty.
- Keep the pane `Draw` call inside the manager's `Draw` so PTY `Winsize` resizes run on the main loop.
- Key handling runs on the main loop: `handleKey` returns `false` to forward an event to the focused pane's `HandleEvent`, which writes keystroke bytes to the PTY.
- While a bracketed paste is active (`pasteActive`), every `EventKey` is forwarded verbatim to the focused pane; prefix/command parsing is bypassed so pasted text can never trigger a multiplexer command.
